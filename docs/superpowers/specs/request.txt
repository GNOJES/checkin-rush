모바일 웹 퍼즐 게임 「체크인까지 5분」을 개발해 주세요.

플레이어가 가상 이메일·메신저·항공사 앱을 오가며 단서를 찾고, 잘못된 예약 정보를 복구해 제한 시간 안에 탑승권을 발급받는 싱글플레이 게임입니다.

기획 설명이나 화면 목업에 그치지 말고, 처음부터 엔딩까지 실제로 플레이 가능한 게임을 구현하고 검증해 주세요. 이 요청은 아래 명세에 따른 로컬 구현과 테스트까지 승인한 것입니다. 외부 서비스 가입이나 공개 배포는 포함하지 않습니다.

## 1. 게임의 목표와 분위기

- 제목: 체크인까지 5분
- 프로젝트명: five-minutes-to-checkin
- 한국어 UI
- 스마트폰 세로 화면 우선, PC에서도 플레이 가능
- 첫 플레이 기준 약 5분 분량
- 익숙한 여행 앱을 사용하는 듯한 화면과 짧은 이야기
- 분위기는 가벼운 긴장감과 현실적인 여행 코미디
- 관찰하고 정보를 연결하면 풀리는 공정한 퍼즐
- 실제 항공사의 절차를 재현하는 서비스가 아니라, 가상의 공항·항공사에서 진행되는 게임

오프닝 상황:

“공항에 도착했다. 탑승권 발급 마감까지 5분.
그런데 앱에는 ‘예약을 찾을 수 없습니다’라고 나온다.
예약을 대신한 친구는 분명 결제가 끝났다고 한다.”

목표는 예약 조회, 이름 정정, 시간 확인, 변경된 탑승구 확인의 네 퍼즐을 해결하고 탑승권을 발급받는 것입니다.

## 2. 첫 버전의 범위

첫 버전은 하나의 고정된 시나리오로 완성해 주세요.

포함:
- 가상 스마트폰 화면
- 이메일·메신저·항공사 앱 3개
- 핵심 퍼즐 4개
- 선택적인 유료 서비스 함정 2개
- 제한시간 모드와 연습 모드
- 단계별 힌트
- 성공·실패 결과 화면
- 다시 플레이
- 간단한 효과음과 음소거
- 모바일 반응형 UI

제외:
- 실제 로그인·결제·SMS
- 서버·데이터베이스·멀티플레이
- 실제 항공사 API
- 실제 LLM을 사용하는 챗봇
- 랭킹·광고·과금
- 첫 버전의 무작위 시나리오

모든 데이터와 대화는 로컬의 가상 데이터로 처리하세요.

## 5. 핵심 퍼즐과 정답 경로

### 퍼즐 1: 예약번호 구분

항공사 앱에서 예약번호와 성을 입력합니다.

- TR-482193을 입력하면:
  “여행사 주문번호로는 조회할 수 없습니다. 항공사 예약번호를 확인해 주세요.”
- Q7M2KD와 HAN을 입력하면 예약 조회 성공
- 영문 입력은 대소문자와 앞뒤 공백을 정규화
- 엉뚱한 값은 오류 안내만 표시하고 진행을 막아 버리지 않기

### 퍼즐 2: 이름 정정

예약 이름 HAN SEOJOON과 여권의 HAN SEOJUN을 비교해야 합니다.

예약 상세에는 “여행 서류와 이름이 일치하지 않아 탑승권을 발급할 수 없습니다”라고 표시합니다.

이름 정정 화면:
- 성과 이름을 구분해 입력
- 게임 속 무료 정정 안내를 읽으면 직접 정정 가능
- HAN / SEOJUN으로 정정하면 통과
- 틀리면 불일치 안내와 재시도

실제 항공사의 이름 정정 정책처럼 설명하지 말고, 이 가상 서비스의 게임 규칙으로 표현하세요.

### 퍼즐 3: 시간대 확인

항공사 앱에서 탑승권 발급 마감 시각을 확인하는 문제가 나옵니다.

질문:
“공항 현지 시각 기준, 탑승권 발급 마감은 언제인가요?”

선택지:
- 14:05 — 정답
- 15:05 — 한국 시각
- 14:35 — 출발 시각

이메일과 앱에 시간대 표시가 명확하게 있어야 합니다.
틀린 선택은 이유를 설명하고 다시 풀 수 있게 하세요.
단순 찍기로 통과해도 진행은 가능하지만 오답 횟수를 결과에 기록하세요.

### 퍼즐 4: 최신 탑승구 확인

최초 안내는 B12, 더 최근 변경 메일은 C08입니다.

항공사 앱의 탑승구 확인 화면에서 현재 탑승구를 선택합니다.
메일의 발송 시각과 변경 문구를 비교하면 C08임을 알 수 있어야 합니다.

- C08 선택 시 통과
- B12 선택 시 “기존 안내입니다. 더 최근 변경 안내를 확인해 주세요.”
- 재시도 가능
- 오답 횟수 기록

네 퍼즐을 완료한 뒤 탑승권 발급 버튼을 누르면 성공합니다.
탑승권에는 올바른 승객 이름, MA204, C08, 12A, 현지 출발 시각을 표시하세요.
바코드는 장식용이며 실제 인증 기능은 없습니다.

## 6. 선택적인 비용 함정

실제 결제처럼 외부로 연결하지 말고 게임 내 금액만 기록하세요.

함정 1:
- “예약 복구 대행 · ₩9,900”
- 선택하면 비용만 기록하고, 무료 조회 경로는 계속 이용 가능
- “대행 접수 완료. 예약번호 확인은 별도로 필요합니다”라고 표시

함정 2:
- “영문 이름 빠른 정정 서비스 · ₩19,900”
- 올바른 이름 입력과 확인 후 선택하면 이름 퍼즐을 해결하지만 비용 발생
- 같은 화면에서 무료 직접 정정 경로도 찾을 수 있게 구성

각 비용은 한 판에 한 번만 청구하세요.
함정에 걸려도 승리할 수 있어야 합니다.
작은 글씨를 못 읽어서 강제로 실패하는 방식은 피하세요.

## 7. 타이머·모드·힌트

제한시간 모드:
- 시작 버튼을 누른 순간부터 300초
- 앱을 바꾸거나 팝업을 열어도 시간 진행
- 탭이 백그라운드에 있어도 경과 시간 반영
- 시간이 끝나면 실패, 이후 조작으로 결과가 바뀌지 않기

연습 모드:
- 제한시간 없이 동일한 퍼즐 플레이
- 결과에 연습 모드라고 표시
- 긴장감 없이 단서와 동작을 확인할 수 있게 구성

힌트:
- 현재 미해결 퍼즐에 맞춰 3단계 제공
- 1단계: 찾아볼 위치
- 2단계: 비교할 정보
- 3단계: 구체적인 정답
- 힌트 사용 횟수 기록
- 힌트 열람 중에도 제한시간 진행
- 각 단계의 힌트를 나중에 다시 볼 수 있게 구성

남은 시간 60초부터 시각적으로 강조하되 과도한 깜빡임은 사용하지 마세요.

## 8. 결과 화면

성공 결과:
- “탑승권 발급 완료”
- 완성된 탑승권
- 소요 시간
- 추가 지출
- 힌트 사용 횟수
- 오답 횟수

엔딩:
- 성공 + 추가 지출 0원: “침착한 여행자”
- 성공 + 추가 지출 있음: “돈으로 해결한 여행자”
- 시간 초과: “공항 카페 단골”

실패 결과:
- “탑승권 발급 마감”
- 완료한 퍼즐 수
- 놓친 단계 설명
- 다시 도전과 연습 모드 버튼

결과 요약 복사 기능을 구현하세요.
공유를 자동으로 실행하거나 외부에 전송하지 마세요.

## 9. 화면과 연출

- 실제 여행 앱처럼 깔끔하고 읽기 쉬운 디자인
- 이메일·메신저·항공사 앱의 색상과 화면 구조를 구별
- 상단에 남은 시간과 진행도 0/4 표시
- 홈 화면에서 3개 앱을 열 수 있고, 언제든 홈으로 돌아올 수 있게 구성
- 앱을 이동해도 작성 중인 입력과 퍼즐 진행 상태 유지
- 새 메일·메시지는 알림 배너와 앱 배지로 표시
- 중요한 알림은 사라져도 해당 앱에서 다시 확인 가능
- 문서 확대와 긴 내용 스크롤 지원
- 앱 전환, 메시지 표시, 탑승권 발급에 짧고 자연스러운 애니메이션
- 애니메이션 때문에 입력이나 결과 판정이 늦어지지 않기
- 버튼음·알림음·성공음·실패음 제공
- 첫 사용자 조작 이후에만 사운드 활성화
- 음소거와 동작 줄이기 설정 제공
- 외부 이미지·폰트·음원에 의존하지 않고 기본 플레이 가능

스마트폰에서는 화면을 충분히 활용하세요.
PC에서는 중앙에 가상 폰을 배치해도 됩니다.
작은 글씨, 스크롤 불가능한 영역, 화면 밖으로 밀려난 버튼이 없어야 합니다.

## 10. 구현 구조

기본 제안:
- React
- TypeScript
- Vite
- CSS
- SVG 아이콘과 가상 문서
- Vitest
- Playwright

기존 프로젝트라면 현재 구조를 먼저 확인하고 적합한 기술을 유지하세요.

게임 상태와 화면 렌더링을 분리하세요.
현재 앱, 화면, 입력값, 퍼즐 완료 상태, 비용 기록, 오답, 힌트, 종료 상태를 일관되게 관리하세요.
useReducer 또는 이에 준하는 명확한 상태 전이 구조를 사용하세요.

시나리오 데이터·문구·힌트·정답은 별도 파일로 분리하세요.
타이머는 콜백이 실행된 횟수가 아니라 실제 경과 시간을 기준으로 계산하세요.
게임 종료와 비용 청구는 중복 실행되지 않아야 합니다.
재시작하면 이전 타이머·메시지 예약·팝업 상태를 모두 정리하세요.

향후 다른 시나리오를 추가하기 쉬운 정도로만 구조화하고, 불필요한 범용 게임 엔진을 만들지 마세요.

## 11. 개발과 검증

다음 순서로 진행하세요.

1. 작업 폴더와 기존 지침 확인
2. 구현 구조와 고정된 정답 경로를 간단히 정리
